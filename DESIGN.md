# Butler design

Butler is a personal agent that runs errands on the Mac mini, through native apps (accessibility tree) and the browser, and learns new errands by watching them done once. You direct it and approve its work from the iPhone or from anywhere on the Mac.

The core object is the **Errand**, not a chat thread. Every surface shows the same Errand at the size that fits it.

This document is the contract for every phase. A pull request that breaks a rule here either changes this document in the same PR, with the reason, or does not merge.

---

## 1. Platform constraints we follow

Checked on 2026-11-10 against Apple's documentation, the WWDC26 sessions and the agent-desktop README. Section 12 lists sources per API.

| Constraint | What it means for Butler |
| --- | --- |
| Liquid Glass sits on the navigation and control layer only (HIG Materials). | Glass on bars, the menu bar popover chrome, floating capsules and controls. Never on Errand cards, receipts or X-ray frames. |
| No glass on glass. Group nearby glass elements in one `GlassEffectContainer` so they blend and morph together. | One container per floating cluster. A glass button never sits on a glass panel. |
| System bars get their look from the system. | No `.background` or `.toolbarBackground` on navigation bars, tab bars or toolbars. Scroll edge effects under every custom bar. |
| Concentric shapes. | `ConcentricRectangle` and container-relative corners. No numeric `cornerRadius:` anywhere. |
| macOS 27 / iOS 27 add a system Liquid Glass transparency slider. System glass follows it automatically; we found no public API to read its value. | Use only system glass so the slider works for free. Verify both ends manually in Settings during the Phase 1 review. Never build a fake glass from blur plus opacity. |
| Foundation Models (OS 27) adds a public `LanguageModel` protocol, `PrivateCloudComputeLanguageModel` (32K context, reasoning levels, no API key) and declarative `DynamicProfile`s that switch model, tools and instructions within one session. | The runner holds one `LanguageModelSession` per Errand and switches profiles between triage, planning, step and recovery. |
| Anthropic ships `ClaudeForFoundationModels` (0.2.3, pre-1.0) conforming to `LanguageModel`. Auth: `.apiKey`, `.appAttest(clientID:)` or `.proxied`. | Claude runs on the Mac runner only and is billed to the Claude subscription (DECISIONS.md D2). Any key lives in the `agentos` keychain. The iPhone never calls a model and never holds a key. Pin the package version; expect API churn before 1.0. |
| agent-desktop (Apache-2.0) reads the accessibility tree as JSON with refs scoped to one snapshot. Retry a failed command only when `error.disposition.retry` is `safe`. It is headless by default (no pointer movement, no focus steal). | Butler's executor loop is snapshot → act on ref → re-snapshot to verify. The retry rule comes from `disposition`, not from matching error codes. |
| Xcode 27's Preview Snapshot MCP tool renders light/dark, orientation, type size, widget timelines and Live Activity toggle states. | Phase proofs are generated by that tool, so every component ships `#Preview`s that cover those axes. |
| App Intents on OS 27: `SnippetIntent`, `ShowsSnippetView`, `.appEntityIdentifier` (with collection annotations), App Schemas, and the `AppIntentsTesting` framework. | Siri, Spotlight, Shortcuts and onscreen awareness all go through one intent layer, tested in Phase 4. |

### Named in the brief, different in the SDK

| Brief says | Reality | What we do |
| --- | --- | --- |
| agent-desktop "FFI library (preferred)" | The FFI is a C library (`libagent_desktop_ffi`) loaded in-process. | **Start with the CLI as a child process** (see DECISIONS.md D4). A child process can be killed in milliseconds, which serves the 1-second kill switch, and a crash in it cannot take the runner down. Move to FFI only if measured latency needs it. |
| Honor `STALE_REF` / `AMBIGUOUS_TARGET` | Both exist; `AMBIGUOUS_TARGET` lists candidate window IDs in `error.details`. Retry safety is in `error.disposition.retry`. | Re-snapshot on `STALE_REF`. On `AMBIGUOUS_TARGET`, pick a window only if exactly one candidate matches the Plan's target app; otherwise the step becomes Needs you. |
| Reading the Liquid Glass slider | No public read API found. | Rely on system materials and test manually. Recheck the SwiftUI docs at Phase 1 start. |
| Background vs foreground intent pairs | Not covered in WWDC26 session 343. | Verify against WWDC25 session 260 at Phase 4 start before designing around it. |
| Colored sidebar icons on macOS 27 | Not confirmed in the docs read so far. | Use `Label` with SF Symbols in the sidebar and let the system render; confirm tint behavior on device in Phase 2. |

## 2. Principles, and how each is enforced

1. **Ambient first, app second.** About 80% of interactions never open the app. *Enforced by:* every flow in the state matrix (section 9) names its ambient surface. A flow that needs the app window is listed in section 6 with its reason.
2. **One object, many sizes.** The Errand is one component family (section 5). *Enforced by:* surfaces compose `Errand*` components; no surface draws its own Errand UI.
3. **Glass is for navigation, never content.** *Enforced by:* the lint rules in section 11.
4. **Interruptions are a budget.** Approvals batch into decision moments. Only destructive or irreversible actions interrupt immediately. *Enforced by:* the runner owns one `InterruptionBudget` that coalesces non-destructive asks for up to 10 minutes, or until the Errand cannot make progress without them.
5. **Proof over promises.** Every step leaves a Receipt. "Done" is a state the UI shows only with evidence attached. *Enforced by:* `Errand.state = .done` requires a non-empty proof set at the type level.
6. **Calm motion with physical meaning.** Springs only, morph rather than replace, and motion explains cause and effect. *Enforced by:* all animation goes through the `Motion` namespace (section 7); `withAnimation(.easeInOut…)` and `.linear` fail lint.
7. **Keyboard and voice are first-class.** *Enforced by:* every user-facing action is an `AppIntent` first; buttons call intents rather than private methods.

## 3. How Butler talks

Butler writes like a chief of staff's status line, not like a chatbot. The same rules apply to every string, from the Dynamic Island to the receipt.

- **Verb first, plain words, no first person.** "Exporting October from Numbers", not "I'm now going to export…". No "Sure!", no "Happy to help", no exclamation marks.
- **Tense carries state.** Present progressive while running ("Exporting…"). Past tense when proven ("Exported Invoices-Oct.pdf"). A question only when it needs you.
- **Every ask is a decision, never an open question.** It states the action, the target and the consequence, and offers a default. "Send Invoices-Oct.pdf to accounting@…? Nothing is sent until you approve." Non-destructive asks may carry a timed default. **Destructive asks never do.**
- **Length follows the surface.** Island: 2–3 words. Live Activity: one sentence. Notification: what, where, why. App: the full receipt.
- **Failures in three parts:** what happened, what Butler already tried, and the one action that fixes it. "Numbers asked to save changes. Tried: Cancel → stale dialog. Fix: open Numbers and close the dialog, then Resume."
- **Confidence is shown, not claimed.** Butler never says "done!" or "successfully". It shows the file, the wireframe and the checksum.
- **Briefings over pings.** Finished errands roll up into a morning and evening briefing (one notification, one Live Activity summary). Only decisions and failures are delivered on their own.

### How Butler works

- **Plan before run.** Every Errand shows its Plan, a short list of steps in plain words, before anything executes. Learned skills skip straight to Run when their trust level allows it.
- **Quiet while running.** Progress lives in the Live Activity and the menu bar ring. No notifications while things go right.
- **Replay before reasoning.** A learned skill replays its recorded steps against fresh snapshots. The model is only called when the UI diverges from the recording. This is the main cost lever (DECISIONS.md D2) and the main speed lever.
- **Overnight queue.** The Mac mini is always on. Errands marked "whenever" run in a quiet window (default 01:00–06:00) and land in the morning briefing.

## 4. The Errand lifecycle

```
Ask → Plan → Run → Proof → Done
         │      │
         │      ├─→ Needs you ─→ (approve / edit) ─→ Run
         │      │                (deny) ─────────→ Done (cancelled, with receipt)
         │      └─→ Failed ─→ (retry / recover) ─→ Run
         └─→ Needs you (plan has an "ask me first" or destructive step)
Any state ─(kill switch)─→ Paused (receipt written within 1 s)
```

| State | Meaning | Ring | Status color (system) |
| --- | --- | --- | --- |
| Ask | Request received, triage running on device | dotted, no fill | `.secondary` |
| Plan | Plan drafted, waiting for start or edit | segments shown, no fill | `.secondary` |
| Run | Executing step n of N | fills per finished step | accent |
| Needs you | Blocked on a decision | holds fill, pulses once on entry | `.orange` |
| Paused | Stopped by you or the kill switch | holds fill | `.secondary` |
| Failed | Cannot continue without recovery | holds fill, red tick at the failing segment | `.red` |
| Proof | Verifying outputs | full ring, shimmer once | accent |
| Done | Proven complete | full ring, check glyph | `.green` |

Color is never the only signal: each state also has a glyph and a label.

## 5. The Errand component family

One family, eight sizes. Every size answers two questions: **what is it doing, and does it need me?**

| Size | Component | Used on | Shows | Controls |
| --- | --- | --- | --- | --- |
| XS | `ErrandGlyph` + `ErrandRing` | Dynamic Island compact and minimal, menu bar extra icon | Skill symbol inside the step ring. Needs you swaps the symbol for `exclamationmark` in orange. | none |
| S | `ErrandLine` | Island expanded, Lock Screen and Mac menu bar Live Activity, widget rows | Current step (one sentence), next step (secondary), step n/N | Pause, Stop (`LiveActivityIntent`) |
| S | `DecisionCard` | Actionable notification, decision stack | Action, target, consequence, destructive marker | Approve / Edit / Deny; long-press previews `XRayFrame` |
| M | `ErrandCard` | Siri snippet, Spotlight result, widget medium/large, popover | Title, `ErrandLine`, last receipt | Context-dependent, all intents |
| M | `SkillCard` | Skills tab, Spotlight, Teach review | Symbol + tint, parameter tokens, trust meter | Run, Edit parameters |
| L | `PlanList` | Popover Quick ask, canvas | Editable steps; destructive steps marked | Reorder, delete, rewrite, "ask me first" |
| L | `ReceiptRow` | Inspector, Receipts tab | Action, result, model, duration, SF Mono caption | Reveal screenshot (blurred by default) |
| XL | `XRayFrame` + timeline | Canvas, inspector, notification preview | Wireframe of the app at that step, acted-on element highlighted, caption | Scrub, reveal screenshot |

Rules for the family:

- Components take an `ErrandSnapshot` value (a plain struct, no live references), so widgets, snippets and Live Activities render the same thing the app does.
- Content surfaces use the content layer: `.background(.background)` or a grouped background. Glass appears only in the floating controls that sit over them.
- The ring fills **by step, not by time**. N is known once a Plan exists; before that the ring shows dotted, unfilled.
- Numerals inside the ring use SF Rounded with monospaced digits. Captions and receipts use SF Mono. Everything else uses SF Pro text styles.

### X-ray replay (hero)

Each step's accessibility snapshot is rendered as a wireframe: windows as outlined containers, controls as labeled shapes, text as gray bars of the right length. The acted-on element is filled with the accent color and labeled with the caption ("Clicked Export in Numbers"). Scrubbing morphs between frames with `matchedGeometryEffect` keyed by stable element identity (role + path + label), so elements that persist glide and new ones fade in. Real screenshots are opt-in per step, captured only when the Policy allows them for that app, and blurred until revealed.

## 6. Surfaces

### iPhone

- **Live Activity + Dynamic Island** for any running Errand: compact = `ErrandGlyph` + `ErrandRing`; expanded = `ErrandLine` + Pause/Stop. Updates arrive by push from the Mac runner.
- **Actionable notifications** for decision moments only. Batched: "2 decisions in Invoices export". Category actions Approve / Deny; Edit opens a compact sheet, not the app.
- **Controls:** Control Center and Lock Screen "Pause Butler" (kill switch) and "Run last errand".
- **Widgets (S/M/L)**, configurable with App Intents: Needs you count; today's finished errands; one-tap favorites.
- **Siri** through App Intents and App Schemas with snippets built from `ErrandCard`.
- **Onscreen awareness:** Errand rows annotated with `.appEntityIdentifier` so "approve the second one" resolves.
- **App window (depth):** tab bar with Now, Skills, Receipts and Search as its own tab; the bar minimizes on scroll.

### Mac mini

- **Menu bar extra:** `ErrandRing` icon; the popover holds Now, Needs you and Quick ask. This is the Mac's home base.
- **Live Activity dedupe:** when an iPhone Live Activity for the same Errand shows in the Mac menu bar, the menu bar extra drops to a static icon for that Errand, so no state is shown twice. Verify this behavior on device in Phase 3.
- **Spotlight:** every intent appears with a parameter summary and suggested entities: "Run errand…", "Teach Butler…", "Show receipts for…".
- **Shortcuts automations:** intents usable from folder, time-of-day and display-wake triggers.
- **Full window:** `NavigationSplitView` with an edge-to-edge sidebar, the Errand canvas and an inspector for proof.
- **Teach mode overlay:** a glass capsule pinned top-center while recording, with a live step count and Stop / Discard. Nothing else on screen changes.

### When the app window is justified

Only these flows need the app window. Everything else must work from an ambient surface.

| Flow | Why it needs depth |
| --- | --- |
| First-run setup and Accessibility permission fix | System Settings deep links plus a guided checklist need a full surface. |
| Teach review (turning a recording into a Skill) | Renaming parameter tokens across many steps needs space and a keyboard. |
| X-ray deep replay | Scrubbing a timeline of wireframes needs width. |
| Policy editing (allowlists, never-touch list, action classes) | Security settings deserve a deliberate, unhurried surface. |
| Trust level changes | Raising autonomy is a considered choice. Lowering it is also available from the Skill's context menu everywhere. |

## 7. Motion

All animation comes from one namespace. Values are starting points and get tuned on device in Phase 1.

```swift
enum Motion {
    static let snappy  = Animation.spring(duration: 0.28, bounce: 0.12) // controls, toggles, ring segment fill
    static let settle  = Animation.spring(duration: 0.42, bounce: 0.18) // card state changes, morphs between sizes
    static let gentle  = Animation.spring(duration: 0.60, bounce: 0.0)  // X-ray scrubbing, large layout moves
    static let reduced = Animation.spring(duration: 0.20, bounce: 0.0)  // Reduce Motion: opacity and color only
}
```

| Event | Motion | Meaning it carries |
| --- | --- | --- |
| Step finishes | Ring segment fills with `snappy`. | Progress is earned one step at a time. |
| Run → Needs you | Ring holds; glyph cross-fades to `exclamationmark`; one scale pulse (1.0 → 1.06 → 1.0) with `settle`. | Butler stopped because of you, not because something broke. |
| Decision approved | Card slides off to the right, haptic `.success`; the next card rises. | Cause (swipe) → effect (gone). |
| Decision denied | Slide left, haptic `.warning`. | |
| Error | Haptic `.error`; red tick appears at the failing segment. No shaking. | |
| Popover open | Glass morphs out of the menu bar icon (`glassEffectID`). | The popover *is* the ring, enlarged. |
| Size change (card → canvas) | `matchedGeometryEffect` on the ring and title with `settle`. | Same object, more room. |

Reduce Motion swaps every positional or scale animation for `reduced` opacity and color changes. The ring still fills, but without bounce. Reduce Transparency and Increase Contrast are handled by system materials. We add nothing on top.

## 8. Visual language

- **Type:** SF Pro text styles everywhere (Dynamic Type). SF Mono for receipts and step captions. SF Rounded, monospaced digits, only for numerals in the ring. No fixed point sizes.
- **Color:** system semantic colors plus one accent, `ButlerAccent`, an indigo with light, dark and increased-contrast variants in the asset catalog (final values tuned in Phase 1). Status colors are system semantics (section 4).
- **Glyphs:** SF Symbols, hierarchical rendering. Each Skill has one symbol and one tint drawn from the system palette.
- **Shape:** concentric corners from the window down to controls via `ConcentricRectangle`. No hard-coded radii.
- **Sound:** none by default. Haptics on iPhone use system patterns via `.sensoryFeedback`.

## 9. State matrix

Each state is designed on every surface where it can appear, in light and dark. ✓ = designed in Phase 1; — = not shown on that surface by design.

| State | Island / Live Activity | Notification | Widget | Siri snippet | Menu bar popover | App |
| --- | --- | --- | --- | --- | --- | --- |
| Empty (first launch, no skills) | — | — | ✓ "Teach Butler your first errand" | ✓ | ✓ | ✓ |
| Running | ✓ | — | ✓ | ✓ | ✓ | ✓ |
| Paused | ✓ | — | ✓ | ✓ | ✓ | ✓ |
| Needs you | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Failed, with recovery | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Stale UI detected | ✓ (as Needs you) | ✓ | — | ✓ | ✓ | ✓ |

| Accessibility permission missing | — | ✓ once | ✓ | ✓ | ✓ guided fix | ✓ guided fix |
| Teach mode recording | — | — | — | — | ✓ | overlay capsule |

Every state is also checked at the largest accessibility text size, with VoiceOver order and labels, with Reduce Motion, and at both ends of the Liquid Glass slider.

## 10. Accessibility

- VoiceOver reads an Errand as one element: "Export invoices, step 3 of 5, exporting October from Numbers, running." Actions are exposed as custom actions (Pause, Stop, Approve, Deny).
- Ring progress is an `accessibilityValue`, not only a drawing.
- At accessibility text sizes, `ErrandLine` stacks vertically and the ring moves above the text; nothing truncates mid-word.
- Swipe-to-approve always has a button equivalent.
- Haptics are never the only feedback.

## 11. Lint rules (Phase 1 adds these as SwiftLint custom rules, run in CI)

| Rule | Pattern it catches |
| --- | --- |
| `no_hardcoded_corner_radius` | `cornerRadius:` or `.cornerRadius(` with a numeric literal |
| `no_custom_bar_background` | `.toolbarBackground(` or `.background(` applied in a toolbar or tab bar context |
| `no_easing_curves` | `.easeIn`, `.easeOut`, `.easeInOut`, `.linear` outside the `Motion` namespace |
| `glass_only_in_chrome` | `.glassEffect(` in files under `Components/Content/` |
| `no_nested_glass` | `.glassEffect(` inside a view that is itself inside a `GlassEffectContainer` child with glass (reviewed by hand; regex flags candidates) |
| `no_fixed_font_size` | `.font(.system(size:` |

Reviewers also check by eye for glass on glass, because a regex cannot fully catch it.
